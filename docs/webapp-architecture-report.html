Inside the Waves web app

expo/ is one of four independent Waves clients — the only one with a public URL. It reads a TideCheck API key and a saved location, fetches tide, wave and wind conditions for Hastings Pier, and turns them into a chart-and-verdict screen that leaves the other three clients' code untouched. This walks the path one page load takes through it: what it's allowed to fetch, what it caches, and where the actual judgement calls live.

01

The path of one page load

From an empty screen to numbers on it — what fires, in what order, and what it's gated on.

Key and location hydrate
useApiKey and useLocation both start undefined rather than defaulting early, while SecureKeyStore and AsyncStorage are still being read — nothing fires a request for the wrong key or place.
Two queries enable at once
Once both resolve, useForecastData turns on a tide query keyed on (stationId, apiKey) and a wave query keyed on (location.id), run in parallel through useQueries.
TideAPIClient checks its cache first
A hit under six hours old in AsyncStorage returns immediately. Otherwise it calls tidecheck.com/api/station/<id>/tides with an X-API-Key header and an 8-second AbortController timeout, then writes the new cache.
WaveAPIClient does the same, against two calls
Open-Meteo's Marine API for wave height, then — independently, so one outage can't take the other down — the Forecast API for wind, precipitation, temperature, sun brightness and cloud cover together.
Raw JSON becomes interpolating series
Points turn into TideSeries / WaveSeries / WindSeries / …, which answer "value right now" and "trend" by linear interpolation — then buildDayInsights() turns those series into the day's worded verdict.
Seven components render
A wave-query error is deliberately left out of the combined error field — wave/wind/rain is a nice-to-have overlay, so its failure never blocks the tide UI or throws a scary error over a non-essential chart.
A silent background top-up
If the cache hit that just landed is over an hour old, an effect quietly calls the cache-bypassing refresh() — the already-rendered screen never blocks on it.
Widget hand-off iOS only
useWidgetSync fires on every key/location change, but syncWidgetConfig() opens with if (Platform.OS !== 'ios') return — on the web build this step runs every time and does nothing.

Cache economics

The same day of use, priced in network calls — one tide call plus two wave/wind calls per full fetch.

SessionCalls, uncachedCalls, as builtWhy
First open of the day33cache empty — 1 tide + 2 wave/wind, always fetched
Reopened 20 minutes later30served straight from AsyncStorage, under the 6h TTL
Left open past the 1‑hour mark33useForecastData's background top-up force-refetches once
Pull-to-refresh / footer's "Force refresh"33forceRefresh() deletes the cache key first, on purpose
8 opens spread across one day243cache absorbs 21 of 24 calls — 87% saved
Retries are off by design. QueryClient sets retry: false for every query — TideCheck's 50-request/day free tier can't absorb a blind retry stacked on top of an already-failed call. On a network error, both clients hand back their last cache instead: stale beats empty.

"It's a walk-on-the-pier judgement — wind band, rain spell, what to wear — not a water-sports one; tide is reported but never scored." — from the file's own tuning comments. Today's sentence and clothing call both narrow the window to "now through the end"; any other day reads the window whole, so the sentence, the clothing call and the bars can never disagree about whether it rains.
05

What only happens on the web build

Same components, same services — four places the platform check actually changes behaviour.

Key storage

expo-secure-store has no web implementation, so SecureKeyStore falls back to window.localStorage — less secure than Keychain, but the key never leaves the device on either path.

Widget hand-off

useWidgetSync still fires on every render, but syncWidgetConfig() checks Platform.OS === 'ios' first — on web, and on Android, it's a guaranteed no-op.

Rendering

The same seven components and the same react-native-svg charts run through react-native-web rather than a native host — no separate web-only component tree.

Shipping

CI runs Biome lint + tsc --noEmit and squash-merges to main; that push runs expo export --platform web and publishes expo/dist to GitHub Pages.

Themes

Dark → Poster → Glass, cycled from one footer toggle — useTheme persists the choice, all three render on every platform this app ships to, web included.

The only public URL

Of the four Waves clients, only this build is reachable without installing anything — raffij.github.io/waves.
